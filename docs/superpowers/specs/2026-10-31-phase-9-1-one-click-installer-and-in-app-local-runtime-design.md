- **Status:** Draft — Awaiting User Approval

## 1. Problem Statement & Goals

During the Release 1.0 packaging test and UX review, three critical gaps were identified:

1. **`electron-builder` v26.18.0 Schema & Packaging Failure:**
   - Running `npx --yes electron-builder --projectDir apps/desktop --win` fails because:
     - `apps/desktop/electron-builder.yml` contains `publish.autoUpdate: false`, which violates the `electron-builder` 26.18.0 JSON schema for `publish`.
     - `apps/desktop/package.json` is missing `description` and `author`.
     - `apps/desktop/build/icon.ico` generated by `build-electron.mjs` is `64x64`, whereas Windows NSIS/Portable packaging requires at least `256x256`.
     - `electron-builder` attempts to traverse workspace `node_modules` unless `files` explicitly packages only the self-contained `dist/**/*`, `build/**/*`, and `package.json`.

2. **One-Command Direct Installation (Orin-style `install.ps1` & `install.sh`):**
   - Users should be able to install or update Ashy with a single command in PowerShell or Bash:
     ```powershell
     irm https://github.com/carlos-edu2367/ashy/releases/latest/download/install.ps1 | iex
     ```
     and on Linux/macOS:
     ```bash
     curl -fsSL https://github.com/carlos-edu2367/ashy/releases/latest/download/install.sh | bash
     ```

3. **Zero-CMD In-App Local Model Lifecycle (`LocalRuntimeManager`):**
   - Users choosing Local AI should **never** have to open `cmd.exe` or PowerShell to install Ollama, run `ollama serve`, or run `ollama pull <model>`.
   - The entire local model lifecycle — detecting the engine, installing Ollama with 1 click if missing, starting `ollama serve` headlessly (`windowsHide: true`), listing local models, downloading (`pull`) models with a live progress bar (`%` and MB/GB), and warming up the model — must happen **100% inside the Ashy app** (both in the First Meeting Onboarding Wizard and in Settings).

## 2. Pillar 1 — `electron-builder` Packaging Fix & Deterministic Release Artifacts

### 2.1 `apps/desktop/package.json`
Add required metadata fields:
- `"description": "Ashy — Companhia virtual local-first com memória seletiva e palco 2D"`
- `"author": "Carlos Eduardo <carlos-edu2367>"`
- `"homepage": "https://github.com/carlos-edu2367/ashy"`
- Add script `"dist:win": "pnpm build && pnpm build:electron && electron-builder --win"`

### 2.2 `apps/desktop/scripts/build-electron.mjs`
- Upgrade `generateAshyPngBuffer` icon generation for `build/icon.png` and `build/icon.ico` from `64x64` to **`256x256`** RGBA PNG wrapped in a valid `256x256` ICO header (`width = 0`, `height = 0` in ICO entry per Windows Vista+ 256px PNG-in-ICO specification) so NSIS and `rcedit` pass icon validation without warnings.
- Force regeneration of `icon.png` and `icon.ico` if existing file size corresponds to the old `64x64` icon.

### 2.3 `apps/desktop/electron-builder.yml`
- Fix `publish` configuration to valid `electron-builder` 26.18.0 schema:
  ```yaml
  publish:
    provider: github
    owner: carlos-edu2367
    repo: ashy
    releaseType: release
  ```
- Set deterministic artifact names so `install.ps1` and `install.sh` can fetch exact filenames:
  - Windows NSIS installer: `AshySetup.exe`
  - Windows Portable executable: `AshyPortable.exe`
  - Linux AppImage: `Ashy-linux-x86_64.AppImage`
  - macOS DMG: `Ashy-mac.dmg`
- Set `npmRebuild: false` and exclude `node_modules` from `files` (`!**/node_modules/**/*`) because `dist/main/index.mjs`, `dist/preload/index.cjs`, and `dist/index.html` are 100% self-contained bundles using only `electron` and built-in `node:*` APIs (`node:sqlite`, `node:crypto`, `node:http`, etc.).

## 3. Pillar 2 — Orin-Style One-Line Installer (`install.ps1`, `install.sh` & `.github/workflows/release.yml`)

### 3.1 `install.ps1` (Windows One-Liner)
- Usage:
  ```powershell
  irm https://github.com/carlos-edu2367/ashy/releases/latest/download/install.ps1 | iex
  ```
  (Also works via `irm https://raw.githubusercontent.com/carlos-edu2367/ashy/main/install.ps1 | iex`).
- Parameters:
  - `-Version` (default `'latest'`, or semver e.g. `'1.0.0'`)
  - `-NoDesktopShortcut`
  - `-Uninstall`
- Behavior:
  1. Resolves release asset URL (`https://github.com/carlos-edu2367/ashy/releases/latest/download/AshySetup.exe` or `.../download/v$normalized/AshySetup.exe`).
  2. Downloads `AshySetup.exe` to `$env:TEMP\AshySetup-$PID.exe` with progress feedback.
  3. Runs `Start-Process -FilePath $setup -ArgumentList @('/S') -Wait -NoNewWindow -PassThru` (NSIS silent install).
  4. If `-Uninstall` is passed, invokes `$env:LOCALAPPDATA\Programs\Ashy\Uninstall Ashy.exe /S`.
  5. Cleans up the temporary installer in `finally`.

### 3.2 `install.sh` (Linux / macOS One-Liner)
- Usage:
  ```bash
  curl -fsSL https://github.com/carlos-edu2367/ashy/releases/latest/download/install.sh | bash
  ```
- Behavior:
  - Downloads `Ashy-linux-x86_64.AppImage` to `~/.local/share/ashy/Ashy.AppImage`, marks it executable (`chmod +x`), creates symlink `~/.local/bin/ashy`, and creates a desktop entry `~/.local/share/applications/ashy.desktop`. Supports `--uninstall` and `--version`.

### 3.3 `.github/workflows/release.yml`
- Triggered on `push: tags: ['v*']` or `workflow_dispatch`.
- Builds Windows (`AshySetup.exe`, `AshyPortable.exe`, `install.ps1`) and Linux (`Ashy-linux-x86_64.AppImage`, `install.sh`) artifacts and publishes them to GitHub Releases via `gh release create`.

## 4. Pillar 3 — In-App Managed Local Model Runtime (`LocalRuntimeManager`)

### 4.1 Architecture & Host Service (`apps/desktop/src/host/local-runtime-manager.ts`)
`LocalRuntimeManager` is owned by `AshyHostKernel` and manages the local AI runtime without any terminal window:

1. **Binary & Server Discovery (`getStatus()`):**
   - Checks if Ollama HTTP API is reachable at `http://127.0.0.1:11434/api/tags` (timeout 1.5s).
   - Locates the `ollama` binary on disk:
     - Windows: `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`, `%ProgramFiles%\Ollama\ollama.exe`, or `where.exe ollama`.
     - macOS: `/usr/local/bin/ollama`, `/opt/homebrew/bin/ollama`, `/Applications/Ollama.app/Contents/Resources/ollama`.
     - Linux: `/usr/local/bin/ollama`, `/usr/bin/ollama`, or `which ollama`.
   - Returns `LocalRuntimeStatus`:
     ```ts
     export interface LocalRuntimeModelInfo {
       name: string
       sizeBytes: number
       family?: string
       parameterSize?: string
       quantizationLevel?: string
       modifiedAt?: string
     }

     export interface LocalRuntimePullProgress {
       model: string
       status: 'starting' | 'pulling' | 'verifying' | 'completed' | 'error'
       phaseText: string
       completedBytes: number
       totalBytes: number
       percent: number
       error?: string
     }

     export interface LocalRuntimeStatus {
       engineInstalled: boolean
       engineBinaryPath: string | null
       engineRunning: boolean
       managedByAshy: boolean
       baseUrl: string
       installedModels: LocalRuntimeModelInfo[]
       recommendedModels: Array<{
         id: string
         label: string
         sizeLabel: string
         vramHint: string
         description: string
         isMultimodal: boolean
       }>
       activePull: LocalRuntimePullProgress | null
       installingEngine: boolean
     }
     ```

2. **Headless Daemon Startup (`ensureEngineRunning()`):**
   - If `engineRunning` is already `true`, returns immediately.
   - If `engineInstalled` is `true`, spawns `ollama serve` in background:
     ```ts
     spawn(binaryPath, ['serve'], {
       detached: false,
       stdio: 'ignore',
       windowsHide: true,
       env: {
         ... sanitizedEnv,
         OLLAMA_HOST: '127.0.0.1:11434',
       },
     })
     ```
   - Polls `http://127.0.0.1:11434/api/tags` every 250ms up to 10s until ready.
   - Tracks child process reference (`managedProcess`) so `kernel.dispose()` cleanly terminates it when Ashy exits.

3. **1-Click Engine Installation (`installEngine()`):**
   - If `ollama` is not installed on the user's machine:
     - On Windows: downloads `https://ollama.com/download/OllamaSetup.exe` via HTTPS stream to `$TEMP/OllamaSetup-<pid>.exe`, emitting `local-runtime:pull-progress` events (`model: 'ollama-engine'`, `percent`, `completedBytes`, `totalBytes`), then runs `OllamaSetup.exe /VERYSILENT /NORESTART` with `windowsHide: true`, and automatically calls `ensureEngineRunning()`.
     - On Linux/macOS: runs official installer or `brew install --cask ollama` with progress feedback.
   - Includes a deterministic test override (`ASHY_LOCAL_RUNTIME_MOCK_DIR` / injectable fetch & spawner) so unit and E2E tests can test the entire install/start/pull pipeline offline in milliseconds.

4. **Streaming Model Pull (`pullModel(modelName)`):**
   - Ensures the engine is running first (`await ensureEngineRunning()`).
   - Sends `POST http://127.0.0.1:11434/api/pull` with `{ name: modelName, stream: true }`.
   - Reads the NDJSON response stream line by line, computing `percent = total > 0 ? Math.round((completed / total) * 100) : ...` and broadcasting `local-runtime:pull-progress` Host Events to the UI.
   - On completion, refreshes `installedModels`, automatically configures the `ollama` provider in `ProviderVault` (`baseUrl: 'http://127.0.0.1:11434/v1'`, `modelId: modelName`), sets `activeProviderId = 'ollama'`, and emits updated `LocalRuntimeStatus`.

5. **Model Deletion (`deleteModel(modelName)`):**
   - Sends `DELETE http://127.0.0.1:11434/api/delete` with `{ name: modelName }` and refreshes `installedModels`.

## 5. Pillar 4 — Protocol, Store & UI Integration (`FirstMeetingWizard.tsx` & `App.tsx`)

### 5.1 Shared Host Protocol (`packages/shared/src/host-protocol.ts`)
- New RPC methods:
  - `'localRuntime:getStatus'` -> `LocalRuntimeStatus`
  - `'localRuntime:ensureRunning'` -> `LocalRuntimeStatus`
  - `'localRuntime:installEngine'` -> `LocalRuntimeStatus`
  - `'localRuntime:pullModel'` (`{ model: string }`) -> `LocalRuntimeStatus`
  - `'localRuntime:deleteModel'` (`{ model: string }`) -> `LocalRuntimeStatus`
- New Host Event:
  - `'local-runtime:status'` (`{ status: LocalRuntimeStatus }`)

### 5.2 First Meeting Onboarding Wizard (`FirstMeetingWizard.tsx`)
When the user selects **⚡ Modo Local / Omni Unificado**:
- Displays the **Gerenciador de Motor Local Integrado (Zero Terminal)** card:
  - **Status badge:**
    - `Motor Local Ativo (127.0.0.1:11434)` (green)
    - `Motor instalado (Parado)` -> button **"Iniciar Motor Local (1 Clique)"** (or auto-starts on mode selection!)
    - `Motor não encontrado` -> button **"Instalar Motor Local Automaticamente (1 Clique)"**
  - **Catálogo de Modelos Locais (1-Click Download & Ativação):**
    - Shows recommended models (`qwen2.5:3b`, `llama3.2:3b`, `gemma3:4b`, `qwen2.5:7b`) with size badge, hardware hint, and status (`Instalado ✓` vs. **`Baixar no App`**).
    - Custom model input + button **`Baixar Modelo`** for any tag.
    - Live **Progress Bar** showing `%`, `MB / GB`, and phase (`Baixando camadas do modelo...`, `Verificando SHA-256...`, `Pronto!`).
  - **Auto-Setup on "Despertar Ashy":**
    - If the user clicks **"Despertar Ashy"** in Local Mode and the engine is stopped, Ashy automatically starts `ollama serve` in the background; if the selected model isn't downloaded yet, it pulls it inline before transitioning to the Studio!

### 5.3 Settings View (`App.tsx`)
- Adds a dedicated **Motor Local & Modelos Offline (Gerenciado pela Ashy)** panel inside `Configurações`:
  - Shows daemon status (`Rodando em segundo plano` / `Parado`), button to Start/Restart or Install engine, list of installed models on disk with size + **"Usar este modelo"** + **"Excluir do disco"**, and 1-click download buttons for recommended/custom models with real-time progress bar.

## 6. Security & Adversarial Safeguards

- **Model Name Validation:** `model` parameter in `localRuntime:pullModel` and `localRuntime:deleteModel` is validated against a strict regex (`/^[a-zA-Z0-9._:/-]+$/`, max 128 chars) preventing command injection or path traversal.
- **No Shell Execution:** `spawn(binaryPath, ['serve'], { shell: false, windowsHide: true })` and `OllamaSetup.exe` execution never invoke `cmd.exe /c` or `powershell.exe`.
- **Loopback-Only Binding:** `OLLAMA_HOST` is explicitly pinned to `127.0.0.1:11434` so the managed daemon never exposes ports on `0.0.0.0` (LAN/public network).
- **Clean Process Lifecycle:** If Ashy spawned the background `ollama serve` process, `AshyHostKernel.dispose()` terminates it cleanly so orphan processes do not accumulate.
